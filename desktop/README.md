# Uploadimg Desktop — first local Rust/Tauri application

This application implements a macOS clipboard-to-candidate loop with **simulated sharing**. It never sends original images to a server. Share creates an inaccessible, visibly fictitious `https://example.invalid/i/{48 lowerhex}` result. Copy changes the clipboard and Open launches a browser only after an explicit result action. The proposed public API, receipts and real uploads remain unimplemented.

## Build and checks

Installed tools and already-cached dependencies only: Rust/cargo 1.92.0, Swift 6.3.3, Xcode SDK 26.5, Node 24.21.0. No npm packages, cargo-tauri CLI, account, signing identity or Apple membership is required. Cargo commands are `--offline --locked --jobs 2`; generated artifacts and module/build caches stay under `desktop/.build`. `Cargo.lock` pins the cached resolution. Run these commands from the repository root:

```sh
bash desktop/scripts/test.sh
bash desktop/scripts/build.sh
open "desktop/.build/Uploadimg Desktop.app"
```

Build creates a manual local `.app` with a native Swift dylib, signs the native component before the outer bundle ad-hoc, verifies deep/strict signatures, and reports `otool` dependencies/rpath. Its identifier is `local.uploadimg.desktop.m1`; the native probe is a separate application. The bundled frontend is compiled into Tauri's custom protocol; no dev server is required. Executors did not launch this application. No notarization, sandbox, distribution, paid account or install/upgrade verification is claimed.

Only macOS 26.6.2 arm64 has build/framework test evidence. The plist API floor of 15.4 does not advertise support for that version. Rust core and platform boundaries are arranged for later Windows/Linux work; those adapters return unavailable and have not been built or tested. macOS build/package scripts require the installed Apple toolchain.

## Current behavior

- On macOS, launch starts in the top menu bar with the main window hidden and no Dock icon. **Abrir Uploadimg Desktop** unhides the application, restores a minimized window, shows it and requests focus/application activation. Closing the window hides it while the process continues; **Salir** exits. Platforms without a native tray keep their initial window visible.
- The menu-bar button uses the web header's image glyph shown in [the shared brand asset](../docs/assets/brand.svg) (`image`, viewBox 24 × 24, stroke 1.75, rounded caps/joins), drawn as an 18-point transparent native template. AppKit supplies the tint for the current menu-bar appearance. Its visible text is removed; the hover tooltip and accessibility label are **Uploadimg**. The web's blue wrapper is not part of this native template, and the existing menu remains unchanged.
- **Generar imagen sintética** creates an in-memory demo. Preview, Ignore and Share are explicit commands. A body notification action previews without sharing; dismissal/Ignore/TTL never authorizes Share. Duplicate Share is accepted once.
- **Clipboard detection starts OFF every process.** Opt-in records local intent but does not reactivate a later process. On macOS, use the existing OS shortcut **Control + Command + Shift + 4** to copy a screenshot; the application does not intercept keys or capture screens. Detection also covers other copied images and cannot classify universal screenshot origin.
- Each newly admitted automatic clipboard image or explicit **Pegar imagen** selects its prepared preview and brings the window forward. Admission never shares automatically. Rejected, stale, duplicate, paused or capacity-limited images request no focus; synthetic generation keeps its prior selection behavior without requesting focus. A delayed clipboard focus request is cancelled if that candidate is no longer live and selected when the main-thread effect runs.
- Image-only reads request PNG/TIFF/JPEG bytes, never strings, HTML, URLs or clipboard file references. Enable/resume/wake establishes a new baseline. Denied/unavailable reads stop detection and expose explicit Paste. General-pasteboard prompts/denial behavior and protected/transient markers remain device checks.
- Pause removes unapproved candidates, prevents reads and drops late/queued image events. Resume/wake uses a fresh baseline; wake preserves an existing pause. The native timer and Rust event/expiry worker continue independently of hidden or throttled WebView JavaScript. Closing the window hides it; the native tray opens it, toggles pause and quits.
- Notifications are requested only through the explicit UI button. Native categories implement Share/Ignore and result Copy/Open, generic content without image thumbnails/filenames, validated opaque IDs and grouping. Permission denial/Focus falls back to the visible pending window/tray without inferring consent. Actual OS action presentation and interaction remain unverified for this application.
- **Dedicated-folder detection is unavailable in this first application.** The UI reports it explicitly. The separate native probe remains the feasibility reference; this app never depends on that probe at runtime.

## Ownership and resource boundaries

`crates/core` uses Rust std only, with deterministic monotonic-millisecond inputs. Rust owns immutable originals, candidate IDs, consent, duplicate suppression, pending/result bounds and expiration. macOS uses continuous monotonic uptime, including sleep, with no wall-clock rollback extension. Native ImageIO validates static frame count/type and dimensions before decode; TIFF is normalized to PNG. The single native worker produces an independent decoded thumbnail at most 512 pixels per edge and encodes only that thumbnail for the UI.

Pending originals are at most 3 / 30,000,000 bytes total / 10,000,000 each, 16,000,000 pixels / 8192 per edge, with a 600-second TTL. Same canonical pixels deduplicate across sources for 30 seconds; fingerprint metadata is bounded at 128. Fake result history is at most 20, expires after 24 hours and retains no original/thumbnail. Restart drops all candidates and fake results; no receipt or credential recovery is implemented.

Swift buffers are borrowed only during a synchronous C callback. Rust copies originals/thumbnail/digest before returning and never stores those pointers. The process-lifetime callback has no allocated context requiring external ownership/free. The callback queue allows at most 3 images / 30 MB originals / 3.3 MB PNG thumbnails plus 32 small control events. Rust drains it every 500 ms; originals and raster/PNG/native intermediates may coexist temporarily with pending originals. Image callbacks carry two independent tokens: a control generation owned exclusively by Rust and a native lifecycle advanced by wake or an applied control. A wake cannot advance or collide with a Rust OFF generation. Native worker completion checks both captured tokens before emitting; Rust checks both again before admitting queued callbacks. A fresh explicit Paste with detection OFF remains allowed. Source/paused checks also reject late image work. Each Rust effect batch receives a monotonic revision under the model lock and carries the full live-ID snapshot. The main-thread native destination rejects old configuration and ID synchronization. Delayed notifications are delivered only while their identity remains live, including after a harmless newer worker tick. A drain with several source changes applies only its final configuration. Native configuration acknowledgments only advance the image lifecycle fence; they preserve candidates admitted before the control according to its source policy. Real wake invalidates all pending candidates, including when its callback waits behind a newer Rust control. Neither event issues another configuration, so neither creates a configure/ack loop. Rust releases state and queue locks before native controls or main-thread operations; disable/pause remains a synchronous native control barrier.

Only summaries and bounded PNG preview data URLs cross Tauri IPC. Originals, arbitrary paths, receipt keys and clipboard raw data do not. Copy/Open accepts a result ID, never a caller-provided URL. UI assets are local; configured CSP excludes remote scripts/styles/images/connect destinations, and the main window has only the eight application command permissions. These are scoped configuration and checks, not a sandbox/isolation or runtime CSP bypass proof.

In-process ImageIO, its encoder and the pasteboard provider do not have a hard allocation/deadline limit. Metadata bounds and a single worker do not establish malicious-decoder resource enforcement. EXIF orientation normalization, comprehensive ICC equivalence, protected clipboard markers, secure receipt recovery, real API compatibility and production distribution remain later work.

## Evidence and manual checks

Validation receipts and source snapshots are retained locally under `desktop/evidence/`; they are excluded from the public repository. Review slices are core/tests, native adapters/FFI/queue, Tauri state/commands/config, and frontend/tests. The full application exceeds 400 authored lines; code is not compressed to meet that threshold. The original evidence was recorded before Git initialization; the repository now records the source and documentation. Rollback removes only `desktop`; explicitly used app preferences/notifications can be cleared through macOS separately.

The parent observed this Tauri application's synthetic Generate/Ignore/Share/Pause-Resume loop before M4-F, with clipboard OFF and no permissions activated. This is prior-snapshot GUI evidence, separate from the executor's automated checks. The later tray runtime checks are recorded separately in the validation receipts: a clean bundle rendered the UI, generated a synthetic preview, shared explicitly, hid on close and reopened from the menu bar with its fictitious result preserved. Remaining device checks include duplicate Share, automatic clipboard focus plus OS allow/deny and the system copied-screenshot shortcut, minimize restoration, actual wake, notification body/actions/dismissal/Focus/result URL, and explicit Copy/Open. Use synthetic images and an explicit private test workflow. No personal folders or the general clipboard were inspected in automated checks. Windows/Linux runtime, older macOS/Intel, hard decoder budgets and public uploads remain NOT_RUN.

M4-F, M4-F2 and M4-F3 correct only effect ordering, independent wake/control invalidation tokens, control acknowledgment semantics and the resume status text. M4-F3 separates configuration acknowledgments from real wake: ON preserves existing candidates; OFF removes clipboard candidates but preserves synthetic ones. A queued real wake still clears all pending candidates even if Rust issued a newer control before draining it. The overall rollback boundary is the effect-batch/native version fencing and associated regression tests/docs; M4-F3 alone changes the two lifecycle-event branches in `model.rs` and their tests/docs. These corrections add no transport or platform feature. See the retained M2-E/M4-F/M4-F2 snapshots and new full snapshot in `evidence`.

The tray/foreground work unit changes `src-tauri/src/main.rs`, `src-tauri/src/model.rs`, `src-tauri/Info.plist` and the matching model tests/docs/receipts. Its independent rollback restores these files from the retained M4-F3 boundary without removing the reviewed lifecycle corrections. Offline tests and bundle signing check the code/configuration boundary; actual startup/menu-bar/hidden-window/unminimize/focus/clipboard behavior requires parent device observation. `source-snapshot-m4-f3.json` retains the before-boundary. No Git commit, permission change or app launch is part of the executor's work.

Tray runtime review initially found a blank main window after menu-bar Show. A macOS application-unhide step was added because application hiding and window visibility are separate API states. Temporary diagnostics showed correct view dimensions/visibility and a loaded local URL; a subsequent document probe observed the full bundled document, and a clean build without diagnostics then rendered normally. The blank-window cause remains inconclusive; successful later observations do not prove unhide alone fixed it. All diagnostic hooks, JavaScript evaluation, native exports and file writes were removed from the product; the native bridge remains byte-identical to the reviewed M4-F3 source.

The later menu-bar icon work unit changes only the native icon/button presentation plus its visual checker/docs/receipts. `bash desktop/scripts/check-menubar-icon.sh` writes offscreen glyph/Aqua/Dark Aqua control PNGs under `desktop/.build/menubar-icon`; it creates no window/status item and changes no system appearance. Native regression checks and a signed offline bundle are recorded separately from live menu-bar/hover/dark-mode checks. `source-snapshot-tray-final.json` retains the immediately preceding tray source boundary. Rollback restores `native/macos/Bridge.swift` from that boundary and removes the icon checker/docs/receipts; no clipboard, activation, notification or upload behavior is changed.
